# GaitTrace 前端未完备性说明

> 本文记录当前前端原型与《GaitTrace 项目说明（需求与工作流）》之间的差距，避免把页面可运行误认为步态筛查能力已经完成。本文是实现状态说明，不是临床意见。

## 当前状态摘要

当前交付的是一个可运行的移动端前端原型：可以查看首页、准备引导、相机预览与计时流程、未测量报告和本机历史页面。项目可以通过单元测试和生产构建。

**当前版本不能完成有效步态测量，也不能用于判断健康状况。** 仓库尚未接入姿态模型、步态事件检测、尺度校准或经过验证的评估规则。界面会明确显示未能测量，不生成虚构的骨架、指标、评分或风险灯号。

## 已实现与未完备项

| 需求 | 当前状态 | 说明与影响 |
|---|---|---|
| 手机端中文界面与主要页面 | 已实现原型 | 有首页、准备、测量、报告、历史页面；支持响应式布局、文字提示和可选语音。 |
| 相机权限和本机预览 | 部分实现 | 可申请浏览器相机权限、显示本机视频，并在离开测量页时停止视频轨道；尚未完成 iOS Safari、Android Chrome 真机兼容测试。 |
| 定距和拍摄质量引导 | 部分实现 | 有手机稳定摆放、镜头高度、全身入镜和直线空间提示；没有距离测量或自动尺度标定，也不能自动检查镜头角度、全身入镜或关键点置信度。 |
| 倒数、走测进度与结束 | 部分实现 | 提供倒数和约 30 秒计时。计时结束不代表系统检测到往返完成；用户需要手动结束，且目前没有分析阶段。 |
| 实时骨架与步态识别 | 未实现 | 尚未集成 MediaPipe 等姿态模型，也没有 33 点推理、骨架绘制、左右踝追踪、有效步态片段选择或低置信度重测提示。 |
| 步态指标和综合报告 | 未实现 | 没有左右对称、步间稳定、步速、步幅计算，也没有经过验证的常模、判定阈值、绿黄红指标或综合评分。报告只展示“未能测量”。 |
| 康复建议 | 部分实现 | 目前是一般活动参考，不是基于测量结果的个性化推荐，也不等同于需求中的三项康复动作处方。页面保留了停止活动和就医提醒。 |
| 本机历史和趋势 | 部分实现 | IndexedDB 可保存报告记录并提供查看、清除功能。现阶段保存的是“未能测量”记录；无有效指标时不会绘制趋势或假造变化。 |
| 恶化预警和前次比较 | 未实现 | 缺少有效的连续测量指标、基线与判断规则，因此不会判定改善、恶化或触发指标预警。固定红旗症状就医提示已显示，但不依赖测量。 |
| 离线使用 | 部分实现，尚未验收 | Service Worker 缓存应用外壳和静态资源；没有模型资源可缓存，因此尚不能满足“断网也能完成走测”。需要部署后验证实际离线启动及关键路径。 |
| 隐私边界 | 已按当前原型实现 | 视频仅用于本机预览，不录制、不上传、不写入 IndexedDB；历史仅存本机报告数据。以后接入模型时仍须保持影像和关键点不离开设备、不持久化。 |
| GitHub Pages 发布 | 已有构建配置 | 可生成 repository path 下的静态资源；实际部署、相机 HTTPS 行为及 Pages 下 Service Worker 离线效果仍需在线验证。 |

## 当前用户流程实际会发生什么

1. 用户可以阅读准备指引并尝试授权相机；也可以跳过相机。
2. 相机获准后，浏览器显示实时预览，页面提供倒数与计时；这不代表系统正在分析步态。
3. 结束后，报告会说明本次没有有效测量，不会给出分数、指标颜色或健康结论。
4. 应用可以在本机保存这条“未能测量”记录；历史页会明确标记无有效步态数据，不会把空值当作零或趋势点。

因此，当前体验适合演示**页面结构、隐私原则和未接入算法时的安全降级**，不适合宣称已实现“30 秒步态筛查”或展示真实评估效果。

## 达到需求目标前仍需完成

建议按以下顺序推进；后续步骤依赖前面的接口与验证结果：

1. **完成姿态模型 Spike**：在目标 iOS/Android 设备测量推理帧率、有效关键点比例、左右踝可区分性、重复测量一致性及有效步态周期覆盖。按需求文档中的五项标准给出 go/no-go；不达标时执行已记录的降级预案。
2. **实现并验证测量服务**：接入本地姿态推理、关键点置信度反馈、步态片段筛选、事件检测和时间戳处理；新增可测试的 `PosePipeline` 和 `GaitAnalysisAdapter` 实现。UI 只消费其结果，不在组件中自行推导医学指标。
3. **完成定距、校准和报告规则**：先验证尺度标定，再实现步速、步幅等校准项；为对称性、步间稳定性和报告阈值提供来源、测试样例与已知误差说明。未通过验证的指标应继续显示不可用，不能补造数值。
4. **打通有效报告与历史预警**：只有收到有效分析结果后才保存对应数字指标；依据有效历史实现前次比较、个人基线和保守预警。没有足够数据时要显示“数据不足”，不能下结论。
5. **完善推荐和重测流程**：如果要满足三项动作推荐，应由适当审核的规则或内容提供适用条件、动作要点和禁忌；低置信度、遮挡或拍摄不合格时提示重测。
6. **完成部署和设备验收**：在 GitHub Pages HTTPS 环境验证 iOS Safari 与 Android Chrome 的相机、语音、页面切换/后台恢复和权限拒绝；确认 Service Worker 缓存模型及静态资源后，断网重走关键流程。

## 验收时应保持的边界

- 只把有来源且通过验证的算法输出呈现为测量结果；计时、示意图和演示内容不得冒充分析。
- 不把没有医学依据的阈值包装成诊断结论；始终展示“筛查，非诊断”和必要的就医提示。
- 摄像头视频、抽取帧和姿态关键点只允许在本机内存中用于实时处理，不上传、不缓存、不写入历史。
- 离线能力、模型性能和跨设备兼容性需要在实际部署和设备上测试；通过本机 `build` 不能代替这些验收。
