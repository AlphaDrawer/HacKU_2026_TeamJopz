## 1. 一句话定位

GaitTrace 是一个**免安装、纯网页**的步态自测工具：腰痛/腰突者把手机架在侧面、横走一个来回，30 秒得到一份大白话"步态体检卡"，并能长期追踪自己的步态趋势，在两次复诊之间**早点发现恶化**。

**Pitch 开场（主人真实故事）**："我自己有腰间盘突出，步态也有问题。如果能早点监控，也许就不会拖到现在。这个工具，就是我当初想要、却不存在的那个东西。"

> **Deck 点题要求（v2 新增）**：答辩材料须主动、反复点题——GaitTrace 不是普通体态检测，而是「**高端专家能力（物理治疗师步态评估）下沉到用不起的地方**」，且创新在于「**姿态感知 + 无量纲指标 + 个人纵向基线**」的组合，而非单一识别技术。避免被评委归入"又一个体态 App"。

## 7. 核心任务链路与拍摄几何（v2 统一）

### 7.1 拍摄几何（全文档唯一口径）
- **侧面矢状面（sagittal）拍摄**：手机侧对行进方向，用户在镜头前**横向走过画面**
- 机位：手机靠墙 / 支架立稳，镜头大致与膝 / 髋同高，与行进路线保持固定距离
- 路线：在镜头前横走，**走出画面一端 → 转身 → 横走回另一端**
- **有效数据只取每趟的中段直线匀速部分；起步、转身、止步段一律剔除**
- 之所以取侧面矢状面：脚踝在前进方向（画面水平轴）的着地 / 离地事件最清晰，利于步态事件检测

### 7.2 用户链路
```
① 打开网页
   └─ 首屏：大按钮「开始走测」+ 一句话说明
② 走测准备引导（3 步）
   ├─ 把手机侧立在行进路线旁，镜头与膝盖同高
   ├─ 用「地砖 / 自己步数」参考走出一段直线路（无需精确量尺）
   └─ 站到起点，点「准备好了」
③ 语音/大字倒计时 3-2-1
④ 走测中（约 30 秒）
   ├─ 横向走过画面，转身走回
   ├─ 实时画骨架 + 进度提示
   └─ 检测到完成往返即结束
⑤ 计算中（2-3 秒动画）：自动剔除转身/起步段，只算中段
⑥ 大白话报告
   ├─ 综合评分 + 一句话总结
   ├─ 指标卡（2 个主指标 + 2 个需校准项）
   ├─ 3 个推荐康复动作（图文 + 禁忌提示）
   └─ ⚠️ 何时必须就医
⑦ 自动存入历史
   └─ 历史页：列表 + 趋势曲线 + 较上次变化
```

**零门槛要求**：全程无注册、无配置、无专业术语；每步有语音或大字引导；**不要求用户精确测量距离**（见 §8 尺度标定）；用户唯一要做的动作是"走"。

## 8. 步态指标定义与策略（v2 分主次）

### 8.1 主指标：无量纲、对距离 / 焦距不敏感（v2 主打）

| 指标 | 大白话 | 含义 | 为何稳健 |
|---|---|---|---|
| **左右对称** | ⚖️ 左右均不均衡 | 左右步态时间 / 动作差异（%） | 比值型，无关于绝对距离与镜头焦距 |
| **步间稳定** | 🔄 稳不稳 / 晃不晃 | 步态周期间的节奏变异性（CV%） | 无量纲，只依赖事件时间间隔 |

> v2 的评分与预警**以这两个主指标为核心**，因为它们在零门槛、无精确量距、不同手机 / 机位下依然可比。

### 8.2 需校准项：步速 / 步幅（v2 降级）

| 指标 | 大白话 | 状态 |
|---|---|---|
| **步速** | 🚶 走得快不快 | **需校准项**：依赖尺度标定，报告中明确标注为"估算 / 参考" |
| **步幅** | 👣 步子迈多大 | **需校准项**：同上 |

**尺度标定（替代精确量 5 米）**：
- 不要求用户拿尺量地；改用**地砖边长 / 用户自身步数 / 已知身高**等易得参照
- 结合 MediaPipe 关键点做**自动尺度标定**（如以画面中可识别的已知长度，或用关键点像素位移 + 参照换算）
- 若无法可靠标定，步速 / 步幅仅作趋势参考或不显示绝对值，**绝不给假精确数字**

### 8.3 判定原则
- 主指标用「文献常模 + **个人纵向基线变化**」双重判定
- 纵向变化（与自己历史比）优先级高于单次绝对值
- 阈值由执行规划师结合文献标定，报告体现置信度

**医学依据**：
- LDH 患者表现为步速↓、步幅↓、步频↓、双支撑时间↑、步间变异性与左右不对称↑（[综述](https://pmc.ncbi.nlm.nih.gov/articles/PMC8990405/)）
- 慢性腰痛者步速显著低于健康人（[Meta分析](https://pmc.ncbi.nlm.nih.gov/articles/PMC9338341/)）
- 单手机视频姿态评估与 VICON 金标准多数参数信度 0.84–0.98（[研究](https://pubmed.ncbi.nlm.nih.gov/38264579/)）

## 9. 报告与预警规则（v2 加强）

### 9.1 报告结构
- 顶部：综合评分（0–100）+ 一句大白话总结
- **常驻声明**：「本结果为**筛查与自我追踪，不构成医学诊断**」
- 中部：2 张主指标卡（绿 / 黄 / 红）+ 2 个需校准项（标注"估算"）
- 下部：3 个康复动作（图文要点 + **禁忌 / 急性期提示**）
- 底部：就医提醒区

### 9.2 就医预警（v2：单次严重异常也触发）
满足以下**任一**即高亮"建议尽快就医"：
- 任一**主指标单次出现严重异常**（红色且超严重阈值，阈值待标定）【v2 新增】
- 任一主指标**连续 2 次**进入红色
- 左右不对称较个人基线明显加重（阈值待标定）
- 步速（估算）连续下滑
- **红旗症状（独立于测量，固定常驻文案）**：出现腿麻、下肢无力、大小便异常等，应立即就诊

> 定位始终是"筛查与追踪，不做诊断"；治疗 / 手术由医生决定。

### 9.3 历史趋势
- 本地保存：日期、综合分、主指标、需校准项
- 趋势曲线 + 每次"较上次：好转 / 持平 / 变差"

### 9.4 康复动作推荐的安全提示（v2 新增）
- 每个动作标注：**适用情况、动作要点、禁忌**
- 明确：**疼痛急性发作期 / 腿麻加重时停止练习并就医**，不在急性期推荐激活动作
- 文案为通用康复常识，具体方案遵物理治疗师 / 医嘱

## 10. 与现有手工方法对比（v2 补步骤数 / 来源）

> 说明：步骤数为按真实操作流程逐条拆解；耗时中 GaitTrace 的「约 30 秒」**需技术侧用秒表实测后回填**；HK$380 价格**需补具体价目来源**。

### 10.1 步骤对比（逐条）

**A. 现有方法——靠感觉（用户实际现状）**
1. 日常活动中留意腰痛 / 腿麻程度
2. 凭记忆与上次感受对比
→ 共 **2 步**；耗时：0 秒（但无任何客观数据，等于盲）

**B. 现有方法——正式物理治疗评估**
1. 预约物理治疗
2. 交通前往
3. 排队等候
4. 治疗师肉眼观察 / 仪器评估步态
5. 获取口头 / 书面反馈
6. 交通返回
→ 共 **6 步**；耗时：数小时；费用：私人物治约 HK$380/次（**价目来源待补**）；公立排期数月

**C. GaitTrace**
1. 手机浏览器打开网页
2. 把手机侧立在路线旁
3. 点「开始」、看引导
4. 倒计时后横走一个来回
5. 查看大白话报告
6. （自动）存入历史看曲线
→ 共 **6 步**，但其中用户实际操作仅约 **30 秒（⏱ 待秒表实测回填）**；费用：免费

## 11. 技术实现思路（不黑箱）

```
手机摄像头视频帧（侧面矢状面）
      │
      ▼
MediaPipe Pose（Web 版，本地离线）
      │ 输出 33 个身体关键点坐标
      ▼
追踪左右脚踝关键点在画面水平轴的轨迹
      │
      ├─ 检测脚跟着地 / 脚尖离地事件（x 方向换向 + y 极值）
      ├─ 左右事件时间差 → 左右对称【主指标】
      ├─ 步态周期时长标准差 / 均值 → 步间稳定【主指标】
      ├─ 自动尺度标定（地砖/步数/身高参照）
      └─ 尺度可用时 → 步速 / 步幅【需校准项】
      ▼
只保留每趟中段直线数据，剔除起步/转身/止步
      ▼
与文献常模 + 个人历史基线对比
      ▼
生成大白话报告 → IndexedDB 存历史
```

- **关键依赖**：MediaPipe Pose（免费、浏览器本地推理、无需服务器）
- **后端**：v1 无后端，纯前端 + IndexedDB
- **语言**：中文界面
- **几何**：侧面矢状面横走；用易得参照 + 自动尺度标定替代精确量距

## 12. 会犯什么错（诚实清单，v2 与 §7 同口径）

| 误差来源 | 影响 | 应对 |
|---|---|---|
| 机位 / 拍摄角度 | 像素位移偏差 | 统一侧面矢状面；引导镜头与膝同高；引导横走 |
| 单目尺度不确定 | 步速 / 步幅不准 | 降级为需校准项 + 自动尺度标定；标不定只给趋势 |
| 宽松衣物 / 遮挡 | 关键点丢失 | 置信度低时提示"没测准，请重走" |
| 转身 / 起步 / 止步 | 事件误判 | **只取中段直线数据，转身段剔除** |
| 设备帧率差异 | 计时偏差 | 按帧时间戳而非帧数 |
| 距离未量准 | 绝对速度偏差 | 不要求精确量距；主指标不依赖距离 |

**承诺**：demo 主动公开误差（与人工秒表 / 实测参照对比），不夸大精度。
